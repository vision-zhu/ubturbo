# UBTurbo 安全说明

## 适用范围

本文说明 UBTurbo 守护进程、客户端 SDK、插件和 SMAP 内核组件之间的信任边界与部署要求。具体文件
权限以发布包和部署环境为准；修改服务账号、安装路径或设备权限时，应重新进行安全评审。

## 信任边界

- UBTurbo 仅提供节点内 Unix Domain Socket（UDS）服务，不监听网络端口，也不提供 TLS 通道。
- 守护进程及其动态加载的插件位于同一进程和信任域。只有经过审核并列入
  `ubturbo_plugin_admission.conf` 的插件才能启用。
- SMAP 的扫描和迁移由内核模块执行。内核模块必须由管理员安装，并与当前运行内核及硬件平台匹配。
- 节点外实体、未获本地文件权限的用户和未准入的插件均位于 UBTurbo 的信任边界之外。

## 权限模型

UBTurbo 应使用专用的非登录服务账号运行。配置、日志、动态库、UDS 文件及 SMAP 设备节点应仅向服务
账号和确有调用需要的主体开放，并遵循最小权限原则。

| 对象 | 推荐控制 | 说明 |
| ---- | -------- | ---- |
| UBTurbo 守护进程 | 专用非特权账号 | 不为常规框架功能授予额外 capability |
| UDS 文件 | 属主/用户组权限 | 只允许受信任的本地调用方连接 |
| 配置和日志 | 仅服务账号读写 | 防止策略被篡改或运行信息泄露 |
| 插件动态库 | 管理员安装、准入配置启用 | 插件与守护进程具有相同进程权限 |
| SMAP 设备和内核模块 | 管理员安装、最小设备权限 | 避免非授权进程直接执行扫描或迁移 |

不要通过放宽目录、socket 或设备节点权限来规避启动和访问问题。生产环境中的账号、用户组、udev 和
systemd 配置应由管理员统一维护。

## 调用参数安全

UBTurbo 不校验调用方提供的 PID 是否有效，也不判断该 PID 是否属于调用方。`PID`、`srcNid`、
`destNid`、迁移地址和迁移比例等参数必须由可信的集群资源管理中心生成并安全下发。

- 对参数实施身份认证、授权、完整性保护和审计。
- 保证迁出与迁入地址具有一致的安全等级。
- 保证虚机或容器用户与远端内存访问主体具有一致的权限。
- 调用前校验参数范围和资源归属，避免对非目标进程或 NUMA 节点执行操作。

## 配置、日志与敏感信息

- 不得在源码、配置或脚本中硬编码密码、Token、Access Key、Secret Key 或私钥。
- 凭证应通过受控环境变量或独立配置文件提供，含凭证的本地文件不得提交到版本库。
- 日志不得记录密码、Token、个人信息、敏感内存内容或完整凭证。
- 配置与日志文件应设置最小访问权限，并按照部署方要求轮换、归档和销毁。

## 部署检查

上线前至少确认：

1. 使用受支持的 aarch64 openEuler 环境，SMAP 模块与运行内核一致。
2. 守护进程使用专用账号运行，UDS、配置、日志和设备文件权限符合最小权限要求。
3. 仅启用来源可信且经过代码审查的插件。
4. 调用链路能够认证请求来源，并校验 PID、NUMA 节点和地址的业务归属。
5. 配置和日志中不存在凭证、私钥、个人信息或敏感内存数据。

发现安全问题时，请通过项目维护方指定的私密渠道报告，避免在公开 Issue 中披露漏洞细节。
